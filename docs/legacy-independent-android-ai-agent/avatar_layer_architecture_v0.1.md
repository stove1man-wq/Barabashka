> **Примечание (D-005, 2026-10-12).** Платформа — Unity. Интерфейс `AvatarRenderAdapter` реализуется в Unity; упоминания Filament и SceneView не применяются.

**Статус:** Архитектурный контракт (Baseline, pre-code)  
**Версия:** 0.1  
**Дата:** 2026-10-08  
**Связанный документ:** Planning & Reasoning Model v0.1

---

## 1. Назначение

Настоящий контракт определяет архитектуру слоя отображения Персоны и 3D-Аватара (`Persona & Avatar Layer`). Документ специфицирует требования к мультиплатформенной изоляции графического движка, структуру динамически заменяемых скинов (библиотеки наборов) и формат синхронизации анимационных состояний с рантаймом ИИ.

---

## 2. Архитектурные принципы слоя отображения

1. **Изоляция графического конвейера:** Ядро ИИ (`Agent Core`) полностью отделено от графического API (OpenGL/Vulkan) и конкретных 3D-библиотек. Нарушение изоляции (например, прямой вызов методов рендеринга из Planner) запрещено.
2. **Формат моделей glTF/GLB как стандарт:** Все заменяемые ассеты (скины) должны поставляться в открытом стандарте `glTF 2.0 (Binarized — .glb)`. Использование закрытых проприетарных форматов запрещено для обеспечения мультиплатформенности.
3. **Асинхронная ленивая загрузка:** Загрузка, распаковка и компиляция шейдеров новой 3D-модели из библиотеки наборов не должны блокировать поток вычислений ИИ (`Main Thread`) или UI-интерфейс ввода.
4. **Скины без встроенного исполняемого кода:** Скин является исключительно набором данных (геометрия, текстуры, скелетная анимация). Модель не может содержать скрипты автоматизации или логику поведения.

---

## 3. Схема архитектурной изоляции (Handoff Pipeline)

```text
       [ Agent Core / State Machine ]
                     ↓ (Логическое состояние: LISTENING, WORKING)
       [ AvatarRenderAdapter (Interface) ]
                     ↓
    ┌────────────────┴────────────────┐
    ↓ (Реализация для Android)        ↓ (Будущая реализация для iOS/Других ОС)
 [ Filament / SceneView Adapter ]  [ SceneKit / WebGL Adapter ]
    ↓                                 ↓
 3D-Аватар на экране               3D-Аватар на экране
```

---

## 4. Спецификация Контракта Адаптера Рендеринга

Каждая целевая платформа обязана реализовать базовый интерфейс адаптера:

```text
AvatarRenderAdapter
 ├─ initialize(containerView)
 ├─ loadAvatarModel(assetUri)
 ├─ setAnimationState(logicalState)
 ├─ triggerFacialExpression(expressionId)
 ├─ setLookAtPosition(x, y, z)
 ├─ setVisibility(boolean)
 └─ onSurfaceDestroyed()
```

---

## 5. Структура Пакета Скина (Библиотека Наборов)

Каждый готовый набор (скин), загружаемый пользователем, должен соответствовать строгому манифесту структуры архива (`.zip` или внутренний контейнер):

```text
skin_package.zip
 ├─ manifest.json          # Метаданные (ID, имя, автор, совместимость костей)
 ├─ model.glb              # 3D-геометрия, PBR-текстуры и базовый скелет
 └─ animations/            # Папка со скелетными анимациями (если не вшиты в GLB)
     ├─ idle.gltf
     ├─ listening.gltf
     ├─ thinking.gltf
     └─ confirmation.gltf
```

### Требования к костной структуре (Rigging Invariant):
Все модели в библиотеке наборов должны использовать единую стандартную иерархию костей (например, упрощенный стандарт *Humanoid Rig*). Это гарантирует, что базовая анимация «мышления» или «внимания» корректно применится как к модели робота, так и к модели абстрактного персонажа.

---

## 6. Синхронизация звука и анимации губ (Lip-Sync)

Для реализации бесшовного голосового режима и конференций закладывается механика амплитудного Lip-Sync:
* При работе TTS (Text-to-Speech) аудио-продюсер генерирует поток значений среднеквадратичной амплитуды звука (`RMS Audio Amplitude`).
* Эти данные транслируются напрямую в `AvatarRenderAdapter` в обход ИИ-ядра каждые 16мс (60 FPS).
* Движок рендеринга деформирует кость челюсти или активирует форму ключа формы (`Blend Shape / Morph Target`) рта модели пропорционально громкости звука, создавая иллюзию речи.

---

## 7. Безопасность отображения стейта

Интерфейс Аватара обязан честно отражать состояние опасности транзакции. 
Если Execution Engine выполняет шаг категории риска `R3/R4`, адаптер рендеринга принудительно блокирует любые декоративные «расслабленные» или «игровые» анимации аватара. Персонаж должен находиться исключительно в состоянии фокуса (`Attention/Awaiting Action`), визуально подчеркивая важность момента для пользователя.
