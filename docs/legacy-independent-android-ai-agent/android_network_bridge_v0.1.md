# Independent Android AI Agent — Android Network Bridge v0.1

> **Статус: Superseded (D-005, 2026-10-12).** Ktor-клиент и манифест Kotlin-оболочки не применяются. Адреса сохраняют смысл: `http://10.0.2.2:11434/...` в эмуляторе, для телефона см. D-008. В Unity разрешение HTTP задаётся в Player Settings (**Allow downloads over HTTP**).

**Статус:** Архитектурный контракт (Baseline, Stage 4)  
**Версия:** 0.1  
**Дата:** 2026-10-08  
**Назначение:** Спецификация Wi-Fi моста между эмулятором/смартфоном Android Shell и локальным сервером Ollama на основном ПК.

---

## 1. Маршрутизация Сетевых Запросов (Network Routing)

В зависимости от физического способа запуска Android-оболочки, сетевой Ktor-клиент внутри `AgentCore.kt` осуществляет адресацию по следующим инвариантам адресов:

1. **Запуск во встроенном эмуляторе Android Studio:**
   Используется зарезервированный петлевой IP-адрес **`http://10.0.2.2`**. Он позволяет виртуальной машине эмулятора напрямую видеть локальный хост (`localhost`) вашего основного ПК.
2. **Запуск на реальном физическом смартфоне:**
   Устройство и ПК должны находиться внутри одной Wi-Fi сети. Используется прямой локальный IPv4-адрес компьютера, полученный через сетевой адаптер, например: **`http://192.168.x.x:11434/api/generate`**.

---

## 2. Разрешение на работу с незащищенным HTTP-трафиком (Cleartext Traffic)

По умолчанию ОС Android блокирует любые сетевые запросы по незащищенному протоколу `http://` (разрешен только `https://`). Так как локальная Ollama работает по HTTP, в манифест оболочки закладывается исключение:

```xml
<!-- AndroidManifest.xml (Внутри тега <application>) -->
android:usesCleartextTraffic="true"
```
