1. Главный принцип офлайн-режима
Агент должен быть максимально полезным в рамках того, что реально можно сделать локально, и при этом честным.

Он никогда не должен притворяться, что может сделать то, для чего нужна сеть.
Правило:
«Сначала сделать всё возможное локально → честно сказать, чего не хватает → предложить варианты».
2. Что агент должен уметь без сети (приоритеты)
Разделим возможности на три уровня:
Уровень 1. Обязательный минимум (делать в первую очередь)

Понимать запрос пользователя и уточнять его
Работать с локальной памятью (краткосрочной + небольшой обучаемой)
Использовать уже сохранённые знания о пользователе и правилах
Планировать выполнение задачи
Выполнять действия, которые возможны полностью на устройстве
Генерировать текст, саммари, списки, черновики
Отвечать на вопросы на основе локальных данных и своей базы знаний
Вести диалог и поддерживать контекст разговора
Соблюдать все правила безопасности (это обязательно даже в офлайне)

Уровень 2. Сильный офлайн-функционал

Работа с локальными файлами пользователя (если разрешено)
Напоминания, задачи, локальный органайзер
Анализ и обработка уже имеющихся у агента данных
Принятие решений в рамках заранее заданных политик
Подготовка действий, которые будут выполнены, как только появится сеть (очередь задач)
Базовое обучение на локальной памяти (очень ограниченное)

Уровень 3. Желательный, но можно позже

Более сложные рассуждения с использованием локальной модели побольше
Работа с аватаром и голосовым интерфейсом в полноценном режиме
Локальный поиск по расширенной базе знаний (если будешь её предустанавливать)

3. Как агент должен себя вести, когда не может выполнить запрос полностью
Рекомендуемый алгоритм ответа:

Честно говорит: «Сейчас нет сети, поэтому я могу сделать только следующее…»
Делает максимум из того, что возможно офлайн.
Предлагает варианты:
Выполнить частично сейчас
Поставить задачу в очередь и выполнить при появлении сети
Уточнить запрос, чтобы сделать больше локально

Фиксирует в локальной памяти, что пользователь хотел, и что не получилось сделать.

4. Архитектурные компоненты офлайн-режима
Минимально необходимый набор:

Offline Decision Engine — ядро, которое решает, что можно выполнить локально
Local Memory Manager — работа с малой обучаемой + контекстной памятью
Local Tool Executor — выполнение только разрешённых локальных инструментов
Task Queue — очередь задач, ожидающих сеть
Security Guard — те же политики безопасности, что и онлайн (без послаблений)
Honesty Layer — модуль, который отвечает за прозрачное объяснение ограничений

5. Важные правила проектирования

Безопасность в офлайне не слабее, чем онлайн.
Локальная модель должна быть достаточно умной для планирования и диалога, но не обязана быть огромной.
Все важные решения и отказы должны логироваться локально.
Пользователь всегда должен понимать, в каком режиме сейчас работает агент (онлайн / офлайн).
