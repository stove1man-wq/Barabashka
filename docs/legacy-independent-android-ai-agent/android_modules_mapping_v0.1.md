## 1. Целевая структура пакетов в Android Shell

При переносе кода симулятора в Android-приложение структура папок внутри `app/src/main/java/com/agent/` будет выглядеть следующим образом:

```text
com.agent.
 ├─ core/                     # ИЗОЛИРОВАННОЕ ЯДРО ИИ (Перенос со Stage 2)
 │   ├─ domain/               # Сущности, контракты возможностей и аватара
 │   ├─ entrypoint/           # Координатор AgentCore
 │   ├─ safety/               # Цензор безопасности и Audit Log
 │   └─ execution/            # Транзакционный движок управления
 │
 └─ shell/                    # МОБИЛЬНАЯ ОБОЛОЧКА (Нативный Android слой)
     ├─ di/                   # Внедрение зависимостей (Конфигурация рантайма)
     ├─ service/              # Фоновые службы (Foreground Service, Assistant Role)
     ├─ render/               # Графика Аватара (Filament / SceneViewAdapter)
     └─ ui/                   # Графический интерфейс Jetpack Compose
         ├─ components/       # Адаптивное поле ввода, кнопка EMERGENCY STOP
         ├─ inbox/            # Интерактивная лента AI Inbox
         └─ theme/            # Цветовая палитра Material 3 Design
```

---

## 2. Контракт стыковки слоев

1. **Модуль `core`** остается абсолютно чистым от импортов `android.*`. Он оперирует исключительно типами данных Kotlin и стандартной Java.
2. **Модуль `shell`** выступает поставщиком контекста операционной системы. При инициализации приложения через DI-контейнер, нативный `FilamentAvatarAdapter` приводится к общему доменному интерфейсу `AvatarRenderAdapter` и передается в `AgentCore`.
