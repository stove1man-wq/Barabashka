## 1. Назначение

Android Shell определяет структуру нативного мобильного приложения, выступающего в роли транзакционной и графической «оболочки» для разработанного ИИ-рантайма (`Agent Core`). Документ специфицирует стек технологий, системные роли ОС Android и интеграцию графического оверлея 3D-аватара.

---

## 2. Технологический стек Мобильной Оболочки

* **Язык разработки:** Kotlin 2.x+
* **Архитектурный паттерн UI:** Clean Architecture + MVVM (Model-View-ViewModel)
* **Декларативный UI слой:** Jetpack Compose (Modern Material 3 Design)
* **3D Рендеринг Аватара:** Google Filament API посредством библиотеки `SceneView` (Jetpack Compose совместимая)
* **Асинхронность и Потоки:** Kotlin Coroutines & Flow (для реактивного стриминга состояний Ядра в UI)

---

## 3. Системная интеграция и роли в ОС Android (Permissions & System Roles)

Для обеспечения ультимативной доступности Агента и работы в режиме оверлея поверх любых сторонних приложений, Shell-оболочка задействует следующие системные контракты:

1. **ROLE_ASSISTANT (Дефолтный Помощник устройства):**
   Регистрация через `VoiceInteractionService`. Позволяет вызывать Агента по долгому нажатию кнопки питания или голосовому триггеру в обход стандартного Google Assistant.
2. **SYSTEM_ALERT_WINDOW (Отображение поверх других окон):**
   Разрешение на отрисовку системного оверлея. Необходим для компактного периферийного присутствия 3D-Аватара в состояниях `MINIMAL` и `WORKING` поверх рабочего стола или активных приложений пользователя.
3. **Foreground Service (Фоновое удержание рантайма):**
   Запуск персистентного сервиса с низким приоритетом уничтожения операционной системой (`Low Memory Killer`), удерживающего поток `ExecutionEngine` активным во время длительных транзакций.

## 5. Модель Интеграции: Перенос Ядра в Android

Разработанный на Stage 2 чистый Kotlin-код симулятора (`domain`, `entrypoint`, `safety`, `execution`) переносится в Android-проект в качестве полностью изолированного модуля (Pure Kotlin Library Module). 
Android Shell подключает его как зависимость, реализуя интерфейсы-заглушки:

* Реализация `AvatarRenderAdapter` переписывается с `ConsoleAvatarAdapter` на **`FilamentAvatarAdapter`** (управление 3D-мешем).
* `ExecutionEngine` вместо сна потока (`Thread.sleep`) начинает дергать реальные Android **`Intents`**, **`ContentResolvers`** (для записи в Календарь устройства) и **`AppFunctions API`** (Android 16+).
