# Связка агента в VS Code с Unity

**Статус:** предложение (D-011). Сделано по документации Unity и общим знаниям; на вашей версии 6000.6.5f1 и вашем ПК ничего не запускалось. Всё, что помечено «проверить», нужно проверить до использования.

## Суть

VS Code-агент (Cline или Continue) видит файлы и терминал. Unity-редактор он не видит: ни Console, ни компиляцию, ни результат запуска. Связка — это способ вернуть агенту обратную связь. Чем она надёжнее, тем меньше вы работаете «почтальоном», копируя ошибки.

Заодно это граница безопасности: чем глубже агент управляет редактором, тем больше ущерба от его ошибки. Поэтому уровни вводятся по одному.

## Уровни

| Уровень | Что получает агент | Цена и риск | Когда |
|---|---|---|---|
| **L0** — файлы и вы | Правит `.cs`, вы смотрите Console в Unity и вставляете ошибки | Ничего не настраивать. Медленно | Работает сейчас |
| **L1** — файлы, лог и тесты из терминала | Читает `Editor.log`, запускает EditMode-тесты в batchmode, видит результат | Нужна настройка один раз; проект нельзя одновременно держать открытым в редакторе | Сразу после M0 (этап M0.2) |
| **L2** — официальный Unity MCP | Читает Console, сцену, ассеты; может менять сцену и запускать действия в редакторе | Бета; нужен проект в Unity Cloud и подписка на AI-инструменты (условия и цену проверить); агент получает управление редактором | После M0, только по вашему решению |

Рекомендация: **L0 сейчас, L1 следом, L2 позже и осознанно**. Основная работа этапов M0–M2 — чистый C# (Core) и тесты, и она целиком закрывается L0 и L1. L2 нужен для работы со сценой и ассетами (аватар, M7), а не для ядра агента.

## Настройка VS Code для Unity (по руководству Unity)

Источник — страница руководства Unity «Visual Studio Code and Unity» для 6.3 LTS. Страницу для 6000.6 получить не удалось: **проверьте её для вашей версии**.

1. Расширения VS Code: **C#**, **C# Dev Kit**, **Unity** (все от Microsoft).
2. В Unity: *Window → Package Manager* → пакет **Visual Studio Editor** (`com.unity.ide.visualstudio`), версия 2.0.20 или новее. Пакет `com.unity.ide.vscode` устарел, не используйте.
3. *Preferences → External Tools → External Script Editor*: Visual Studio Code, затем *Regenerate project files*.
4. Открывайте в VS Code папку, где лежит `Assets/` (после D-009 — корень репозитория с `unity/`; следите, чтобы C# Dev Kit нашёл `.sln` или `.csproj`).

Результат: у агента и у вас работают подсветка, IntelliSense и ошибки компилятора **в VS Code**. Это уже снимает часть ошибок до перехода в Unity. Проверка: в `.cs` внесена намеренная ошибка → она подчёркнута в VS Code.

## L1 подробно

**Идея.** Агент сам запускает проверку и читает результат.

1. **Лог редактора.** `%LOCALAPPDATA%\Unity\Editor\Editor.log` содержит ошибки компиляции и вывод `Debug.Log`, пока редактор открыт. Агент читает его файлом. Ограничение: лог — одна большая лента, агент должен смотреть только хвост (`Get-Content -Tail 200 -Encoding UTF8`).
2. **Тесты в batchmode.** Команда (из памяти, **проверить по документации Unity 6000.6 и вашему пути установки**):

   ```
   "<путь к Unity.exe>" -batchmode -nographics -projectPath "<путь к проекту>" -runTests -testPlatform EditMode -testResults "<файл>.xml" -logFile "<файл>.log"
   ```

   Ограничения: проект не должен быть открыт в другом экземпляре редактора; на первом запуске идёт импорт, это долго. Тестовая сборка требует пакет Unity Test Framework (проверить, что он есть в `Packages/manifest.json`; добавление пакета — по согласованию, `AGENTS.md` §5).
3. **Что тестировать.** Только Core (чистый C#, `asmdef` без `UnityEngine`): переходы состояний, валидация цели, выбор стратегии, STOP. Это совпадает с критерием 9 из M2. Код, зависящий от сцены, этим способом не проверяется.
4. **Точная команда записывается** в `PROJECT_STATUS.md` после того, как она реально сработала на вашем ПК, и не раньше.

**Критерий L1:** агент по вашей просьбе (а) находит в `Editor.log` намеренно внесённую ошибку компиляции и называет файл и строку; (б) запускает один EditMode-тест из терминала и показывает результат.

## L2 подробно: официальный Unity MCP

Что известно (по документации Unity, на момент написания, бета):
- Пакет `com.unity.ai.assistant` в проекте; редактор запускает мост (relay), к которому подключается MCP-клиент. Путь релея в Windows: `%USERPROFILE%\.unity\relay\relay_win.exe --mcp`.
- Подключение требует подтверждения в диалоге Unity.
- Нужен проект, привязанный к Unity Cloud, и доступ к AI-инструментам (пробный период или подписка). Условия и цену на сегодня **проверьте на странице Unity**, я их не подтверждал.

Что неизвестно и надо проверить:
- Совместимость с Cline и Continue (оба умеют MCP-серверы, но поддержка конкретно этого релея не проверена).
- Что именно можно делать из MCP на 6000.6 и как ограничить права до чтения.

Риски:
- Агент получает управление редактором: может изменить сцену, ассеты и настройки. Правила `AGENTS.md` §8 (не менять Player Settings и пакеты, `.meta`/`.unity`/`.prefab` только через редактор) для L2 становятся главной защитой.
- Бета: поведение и условия могут измениться.
- Сторонние MCP-пакеты для Unity существуют, но их надёжность и безопасность мне неизвестны; без отдельной проверки не рекомендуются (`AGENTS.md` §5).

Порядок включения, если решите: отдельная ветка git; сначала только чтение Console и иерархии; автоодобрение действий выключено; изменения сцены — только через подтверждение; результат записать в `DEVELOPMENT_LOG.md`.

## Правила для агента при работе с Unity (кратко, подробнее в AGENTS.md §8)

- Меняй `.cs` и `asmdef`. Не меняй `.meta`, `.unity`, `.prefab`, `.asset`, Player Settings и `Packages/manifest.json` без согласования.
- Не запускай Unity в batchmode, пока проект открыт в редакторе; спроси.
- «Код написан» ≠ «компилируется» ≠ «тест прошёл» ≠ «проверено на эмуляторе». Указывай, какой уровень достигнут.
- Не вставляй в Unity-код API по памяти: сверяй с документацией версии 6000.6.

## Разделение труда

Архитектор (старшая модель в чате) ставит задачу карточкой по шаблону из `ROLE_ARCHITECT.md`. Исполнитель в VS Code пишет код и сам проверяет его по доступному уровню связки (L0 или L1). Отчёт по `AGENTS.md` §12 вы приносите архитектору вместе с diff или ссылкой на коммит.
