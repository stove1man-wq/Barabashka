# Настройка Cline и Continue в VS Code

Платформа проекта — Unity (D-005). В VS Code установлены два агента: Cline и Continue. Правила для обоих хранятся в одном месте, `AGENTS.md`.

## 1. Как агенты получают правила

| Агент | Откуда читает правила | Что для этого сделано |
|---|---|---|
| Cline | `AGENTS.md` в корне рабочей папки; также `.clinerules/` | Читает `AGENTS.md` напрямую. Включается и выключается в меню Rules (значок весов под полем ввода) |
| Continue | `.continue/rules/*.md` в корне рабочей папки | Правило `.continue/rules/01-agent-tool-use.md` (`alwaysApply: true`) уже велит следовать `AGENTS.md`. Ваши диагностические коммиты намекают, что Continue может подхватывать `AGENTS.md` и сам; я этого не проверял |

Правила не копируются в `.continue/rules/` и `.clinerules` (там только ссылки), чтобы версии не разошлись. Меняете правило — меняете `AGENTS.md`.

Если у Continue с моделью начинаются сбои с инструментами (печатает JSON вместо вызова), первое подозрение — объём правил. Гипотеза, не установленный факт: проверьте отдельно, меняя одну переменную, как в ветке `diagnostic/disable-agent-instructions`.

Проверка после первого запуска:
1. В меню Rules Cline виден и включён `AGENTS.md`.
2. В Continue подключено правило «Reliable Tool Execution». Если нет, проверьте, что папка `.continue/` лежит в корне открытой рабочей папки.

## 1а. Если агент не создаёт и не правит файлы

Гипотезы по вероятности, не установленные факты. Меняйте по одной переменной (`AGENTS.md` §6) и проверяйте одной и той же просьбой: «Создай файл test.txt со словом ok».

1. **Режим.** В Cline режим Plan файлы не пишет. Нужен Act.
2. **Подтверждение.** Перед записью Cline показывает кнопку подтверждения. Без неё файл не меняется. Автоодобрение записи — меню Auto-approve под полем ввода.
3. **Контекст.** Документация Ollama для Cline требует окно не меньше 32K токенов (поле Context Window в настройках Cline). Если окно меньше, модель может не увидеть описание инструментов и писать код в чат вместо вызова инструмента.
4. **Compact Prompt.** Документация Cline советует для локальных моделей включить *Use Compact Prompt* (*Settings → Features*).
5. **Модель.** Нужна модель, которая поддерживает вызов инструментов. `llama3.1:8b` может быть слабой для роли агента: Continue с ней вёл себя так же (тестовые файлы 2026-10-09). Если пункты 1–4 не помогли, смените модель (кандидат из документации Ollama: `qwen3`) и повторите ту же просьбу. Результат запишите в `DEVELOPMENT_LOG.md`.

Если Cline и Continue ведут себя одинаково, причина скорее в модели и контексте, чем в расширении. LM Studio вместо Ollama сам по себе ничего не меняет, пока модель та же.

Источники: [Ollama: Cline](https://docs.ollama.com/integrations/cline), [Cline: Ollama](https://docs.cline.bot/provider-config/ollama).

## 2. Рабочая область

**Сейчас.** Unity-проект ещё не в этом репозитории (`PROJECT_STATUS.md`), поэтому агентам нужны обе папки. Создайте файл `independent-agent.code-workspace` (например, в `C:\Users\max\Documents\Projects\`):

```json
{
  "folders": [
    { "name": "docs", "path": "independent-android-ai-agent" },
    { "name": "unity", "path": "IndependentAgentUnitySpike/IndependentAgentUnitySpike" }
  ],
  "settings": {
    "files.exclude": {
      "**/Library": true,
      "**/Temp": true,
      "**/Logs": true,
      "**/obj": true
    }
  }
}
```

Откройте его: *File → Open Workspace from File…*. В многокорневой области я не подтвердил, из какой папки Cline берёт `AGENTS.md`. Если правила не видны в меню Rules, откройте в VS Code саму папку `independent-android-ai-agent`.

**После переноса проекта (D-009, предложение).** Unity-проект в папке `unity/` внутри этого репозитория: рабочая область — одна папка, `AGENTS.md` и `.continue/` в её корне, и агенты видят код и документацию вместе. Файл `.code-workspace` тогда не нужен.

## 3. Два агента: как не мешать друг другу

- Файлы в данный момент правит один агент. Перед сменой агента закройте задачу или сделайте коммит.
- Предлагаемое разделение (можно изменить в `AGENTS.md`, раздел 9): Cline — задачи по репозиторию (многошаговые, с запуском команд); Continue — быстрые вопросы, правки выделенного фрагмента, автодополнение.
- Один и тот же вопрос обоим агентам не задавайте: это путь к двум версиям правки.

## 4. Права агента

Автоматически разрешайте только чтение файлов в проекте. Подтверждение вручную: запись файлов (на первое время), команды терминала, всё, что удаляет, `git commit`, `git push`, установка пакетов. Это совпадает с `AGENTS.md`, раздел 10.

## 5. Unity (6000.6.5f1)

- *Preferences → External Tools → External Script Editor*: VS Code.
- *Project Settings → Editor → Asset Serialization Mode*: **Force Text**.
- Исключения для git — в корневом `.gitignore` (`Library/`, `Temp/`, `Logs/`, `Builds/`, `UserSettings/`, `*.apk`).
- Агент не видит Unity Console. Копируйте текст ошибки вручную или дайте ему читать `%LOCALAPPDATA%\Unity\Editor\Editor.log`.
- Android: добавьте `%LOCALAPPDATA%\Android\Sdk\platform-tools` (путь по умолчанию в Android Studio, проверьте у себя) в PATH, тогда `adb` работает как обычная команда. Логи писать в файл: `adb logcat -d > logcat.txt`.
- Связка VS Code ↔ Unity (расширения, чтение `Editor.log`, тесты из терминала, официальный Unity MCP): `docs/agent/UNITY_BRIDGE.md`. MCP-мост редактора пока не подключайте: сначала закройте M0 и M0.1 из `NEXT_STEPS.md`.

## 6. Ритуал сессии

**Начало (вставьте в первый чат):**

```
Прочитай AGENTS.md, PROJECT_STATUS.md, DECISIONS.md и NEXT_STEPS.md.
Кратко скажи: каково проверенное состояние проекта, какой этап текущий и каков его критерий завершения.
Затем предложи план первого шага и дождись моего подтверждения.
```

**Конец:**

```
Подведи итог по формату отчёта из AGENTS.md.
Обнови PROJECT_STATUS.md, DEVELOPMENT_LOG.md и при необходимости DECISIONS.md и NEXT_STEPS.md.
Подготовь сообщение коммита и покажи diff. Не коммить до моего подтверждения.
```

**Если агент пошёл по кругу:** «Остановись. Опиши, что проверено, какая гипотеза и какие данные нужны. Не меняй код.» Это правило двух попыток из `AGENTS.md`, раздел 6.

**Если агент ошибся:** добавьте правило в `AGENTS.md` (одной строкой в подходящий раздел), а не только исправляйте результат.

**Роли (D-010):** Cline и Continue — исполнители. Архитектор — старшая модель в отдельном чате; цикл «карточка → исполнение → отчёт → проверка» описан в `docs/agent/ROLE_ARCHITECT.md`. Исполнитель не принимает архитектурных решений и при неясности задаёт один вопрос.

## 7. Проверка, что всё настроено

1. В новом чате отправьте фразу начала сессии. Агент должен пересказать: платформа Unity (D-005), прототип в эмуляторе получает ответ Ollama (по сообщению владельца), Unity-проект ещё не в репозитории, текущий этап M0.
2. Спросите: «Какие файлы ты читал?» — список должен содержать все четыре.
3. Попросите добавить зависимость. Агент должен отказаться и запросить согласование.
4. Повторите шаги 1–3 в Continue.
