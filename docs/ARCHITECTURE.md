# ARCHITECTURE: Barabashka

Единый документ для разработчика и ИИ-агентов. При конфликте с перепиской прав этот файл.

## 1. Принципы
1. Блоки независимы: интерфейс, ядро, голос, мозг, сеть, плагины. Связь только через `Barabashka.Contracts`.
2. Интерфейсы пользователя фиксируются заранее и не меняются без обсуждения.
3. Уровень приложения (базовый / средний / высокий) = набор подключённых реализаций, а не отдельная программа.
4. Сеть необязательна: без сборки `Network` приложение собирается и работает офлайн.
5. Язык не вшит в код: он приходит как данные (`Utterance.LanguageCode`, языковые пакеты).

## 2. Сборки (Assembly Definitions) и допустимые зависимости
```
Contracts   ->  (ничего; noEngineReferences)
Core        ->  Contracts
UI          ->  Contracts
Voice.*     ->  Contracts          (по сборке на реализацию: Voice.Whisper, Voice.Sherpa ...)
Brain.*     ->  Contracts          (Brain.Isolated, Brain.Ollama, Brain.Cloud)
Network     ->  Contracts
Tools.*     ->  Contracts
App         ->  Contracts          (общие утилиты: MainThreadDispatcher, VoiceInputChannel, заглушки)
Composition ->  все выше           (единственное место, где блоки соединяются; сюда переедет AppBootstrap)
```
Стрелка в обратную сторону или между соседями (например, `Voice` -> `Brain`) запрещена.
Все события и данные между блоками идут через интерфейсы и типы из `Contracts`.

## 4. Потоковый ввод речи
- Реплика приходит двумя видами событий: `OnPartial` (текст по мере речи, может меняться) и один `OnFinal` (фраза закончена).
- Мозг получает только финальные реплики. UI показывает и промежуточные (строка «слышу: ...»).
- События могут идти из любого потока. Всё, что трогает Unity API, переходит в главный поток через `IMainThread` (реализация: `MainThreadDispatcher`).
- Микрофон читается через `UnityEngine.Microphone` (кроссплатформенно), без внешних процессов и без PowerShell.
- Эхо: пока агент говорит, распознавание ставится на паузу (`StopListening` на время `OnStarted`..`OnFinished`).

Движки (подключаются независимо друг от друга):
- **Whisper** (первая реализация, многоязычная, язык определяется автоматически, офлайн). Whisper не потоковый по природе: «поток» эмулируется скользящим окном по последним секундам звука, задержка порядка 1-2 с и зависит от модели и железа. Готовая обёртка для Unity: whisper.unity (проверить актуальную версию, поддержку Unity 6 и лицензию в её репозитории).
- **Настоящий потоковый движок** (sherpa-onnx streaming и т.п.): слова появляются быстрее, но модель обычно под один язык. Подключается как вторая реализация `ISpeechRecognizer` без правок остального кода.

## 5. Языки
- Базовая политика: распознавание и озвучка выбираются по коду языка; если для языка нет пакета, работает многоязычный запасной вариант (Whisper).
- Языковой пакет = папка с `manifest.json` (`LanguagePackManifest`), `intents.json` (фразы для правил), `responses.json` (шаблоны ответов); необязательно: модель распознавания и голос.
- Правила `IsolatedBrain` переезжают из кода в `intents.json`. Брейн на LLM язык понимает сам, пакет нужен ему только для озвучки и строк интерфейса.
- Пакеты не коммитятся в Git целиком, если тяжёлые (модели): папка `Assets/StreamingAssets/models/` в `.gitignore`.

## 6. Уровни (CapabilityProfile)
| Уровень | Мозг | Слух | Голос | Сеть |
|---|---|---|---|---|
| Basic | IsolatedBrain (правила) | текст или Whisper tiny | системный/нет | нет |
| Standard | малая LLM (локально или Ollama в сети пользователя) | Whisper base/small | Piper/системный | по выбору |
| Advanced | крупная LLM с инструментами, память | Whisper small+ | Piper | по выбору |

Онлайн-режим не уровень, а дополнительные `IBrain` и `IAgentTool`. При пропаже сети агент возвращается на локальный `IBrain` из профиля.
Лицензии моделей и голосов проверяются до включения в сборку (особенно для коммерческого использования).

## 7. Правила для разработки
- Новые файлы создаются инструментами записи файлов, не командами терминала (PowerShell портит `$` и `\`).
- Файлы переносятся между папками через Unity, чтобы не терять `.meta`.
- Один блок = одна сборка = одна папка в `Assets/Scripts/`.
- В `Core` и `Contracts` нет `MonoBehaviour` и UI-типов (кроме явно оговорённых переходных скриптов).
